# Radical Pipelines conventions — Day One Importer

## Issues

All tasks are GitHub issues in https://github.com/Automattic/day-one-to-wp. Manage them with the `gh` CLI.

## Pipeline base slug

`<issue-number>-<short-description>` where issue number is the GitHub issue number. Examples: `57-videos`, `60-gif`, `43-custom-post-type`.

## Artifact folder

`pipelines/<pipeline-slug>/` in the repository root, with one numbered subfolder per phase (`0-prompt/`, `1-spec/`, …).

The `pipelines/` folder is **gitignored**: artifacts stay local-only and are never committed or pushed. Phase steps that say "commit the artifact" are satisfied by writing the file to disk; only code and test changes are committed. Phase completion is judged by artifacts on disk plus code commits on the branch.

## Worktrees

All work for a pipeline happens inside a Claude Code worktree. Never modify files in the main working directory, never use raw `git worktree`, and never `cd`.

- **Create and enter:** `EnterWorktree({ name: "<pipeline-slug>" })`. Creates the worktree at `.claude/worktrees/<pipeline-slug>` and enters it.
- **Re-enter an existing worktree:** `EnterWorktree({ path: ".claude/worktrees/<pipeline-slug>" })`.
- **Exit:** `ExitWorktree`.

Note: the artifact folder lives inside the worktree copy of the repo (`pipelines/` is gitignored there too).

## Branch names

Derived automatically by `EnterWorktree` from the worktree name: `worktree-<pipeline-slug>`. Do not choose branch names independently. When opening the PR, the head branch is this worktree branch.

## Team spawning

Every autonomous workflow that spawns agents must use exactly one Claude Code team via `TeamCreate({ name: "<pipeline-slug>" })`. Agents in the same team address each other directly via `SendMessage`; the orchestrator spawns, monitors, and waits — it does not relay between healthy agents.

## Health monitoring

Use Claude Code's bundled `/loop` skill. Only the autonomous workflow launches the monitor.

- **Start:** `/loop 5m <prompt>` with the template from the skill's `reference/health-monitoring.md`.
- **List:** `/loop-list`. **Cancel:** `/loop-kill <id>`.

## Commit format

Imperative mood, sentence case, no trailing period, agent name in parentheses. Examples:

- `Add CPT registration behind importer setting (code-writer)`
- `Fix nonce check on post-type option (code-reviewer)`

## Project guardrails (pass to every agent)

- The plugin is mid-WordPress.org review: WordPress Plugin Check must stay at **zero findings** on the dist package (`npm run plugin-zip`, check via wp-env).
- Follow the established security patterns: nonces + capability checks on every input path, field-level sanitization, late escaping, all writes under `wp_upload_dir()` subfolders.
- `composer run lint:php` (PHPCS WordPress-Core/Docs/Extra) must pass clean.
- `php tests/pure-helper-tests.php` and the wp-env e2e (`wp eval-file tests/wp-env-import-sample.php`) must pass.
